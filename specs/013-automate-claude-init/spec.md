# Feature Specification: CLAUDE.md生成とコミットの自動化

**Feature Branch**: `013-automate-claude-init`

**Created**: 2026-09-13

**Status**: Implemented

**Input**: User description: "SDD化の完了案内で「/initを実行してCLAUDE.mdを生成する」「生成されたCLAUDE.mdをコミットする」という2手順を、利用者による手動実行から、アプリ自身が自動実行する6番目の導入手順に変更する。"

**012との関係**: 012は完了案内に「`/init`実行」「CLAUDE.mdをコミット」という2つの**手動**手順を追加した。本フィーチャーはこの2手順をアプリが**自動実行**する6番目の導入手順に置き換え、完了案内からは該当の2行を削除する。

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 「生成」1回でCLAUDE.mdまで用意される (Priority: P1)

利用者が対象フォルダを選んで「生成」を押すと、既存の5手順（uv導入・specify CLI導入・VS Code拡張導入・Spec Kit足場の配置・Git初期化と初回コミット）に続けて、Claude Code CLIによる`/init`実行でCLAUDE.mdが自動生成され、そのままコミットまで完了する。利用者はVS CodeでClaudeパネルを開いて`/init`を手打ちする必要がなくなる。

**Why this priority（この優先度である理由）**: 012では「/init実行」「CLAUDE.mdコミット」を案内するだけで、実際に行うのは利用者だった。参考にしたセットアップ手順書の意図（手順08で/init直後にコミットする）を、案内するだけでなくアプリ自身が実行することで、SDD化の完了時点で実際にCLAUDE.mdが揃っている状態にできる。

**Independent Test（独立したテスト方法）**: 未導入の対象フォルダで「生成」を実行し、完走後に対象フォルダ直下にCLAUDE.mdが存在し、`git log`に「CLAUDE.md を追加」のコミットが記録されていることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** 対象フォルダが未導入（uv・specify CLI等が無い状態）、**When** 「生成」を実行して全手順が成功する、**Then** 結果一覧に6手順目として「CLAUDE.md の生成とコミット」が「成功」で表示され、対象フォルダ直下にCLAUDE.mdが存在し、コミット済みになっている
2. **Given** 対象フォルダに既にCLAUDE.mdが存在する、**When** 「生成」を再実行する、**Then** 6手順目は「スキップ」と表示され、CLAUDE.mdは上書きされない
3. **Given** Claude Code CLI（`claude`）がPATH上に見つからない環境、**When** 「生成」を実行する、**Then** 6手順目は「失敗」と表示され、理由に`claude`が見つからない旨が示される。5手順目までの結果には影響しない
4. **Given** `/init`の実行がタイムアウトまたはエラーで終了する、**When** 結果一覧を確認する、**Then** 6手順目のみが「失敗」と表示され、それより前の5手順の結果は変化しない（ロールバックされない）

---

### User Story 2 - 完了案内から不要になった手動手順が消える (Priority: P2)

CLAUDE.mdの生成とコミットが自動化されたことで、完了案内（次にすべきことの一覧）から「`/init`を実行する」「CLAUDE.mdをコミットする」という、もう不要になった2つの手順が消え、利用者は本当に自分で行うべき手順（VS Codeを開く、テスト方針を決めて憲章を制定する、`/init`を再実行する）だけを読む。

**Why this priority（この優先度である理由）**: User Story 1で実処理を自動化しても、案内文言が古いまま（既に完了した作業をもう一度行うよう促す）だと利用者が混乱する。案内の更新は自動化そのものより優先度は下がるが、同じ変更の一部として必須。

**Independent Test（独立したテスト方法）**: SDD化を成功させ、表示される完了案内を確認し、「/initを実行する」「CLAUDE.mdをコミットする」という文言が無く、残りの手順（VS Codeを開く／テスト方針決定/憲章制定／`/init`再実行）が正しい順序・番号で表示されることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** 全6手順が成功した、**When** 完了案内を確認する、**Then** 「/initを実行する」「CLAUDE.mdをコミットする」という文言（012で追加されたもの）が表示されない
2. **Given** 全6手順が成功した、**When** 完了案内を確認する、**Then** 残りの手順（VS Codeを開く→テスト方針決定と憲章制定→`/init`再実行）が1から順番に振り直された番号で表示される
3. **Given** 6手順目（CLAUDE.md生成）が失敗した、**When** 失敗時の案内文を確認する、**Then** 従来通り「一部の手順が失敗しました」という文言が表示され、成功時の案内（手順一覧）には変更がない

---

### Edge Cases（エッジケース）

- `claude`コマンドが認証されていない（ログインしていない）環境で実行するとどうなるか? → 他の外部コマンドと同様、コマンドは起動できるが失敗で終了し、`Brief()`が実際のエラー内容を結果一覧に表示する。自動ログインの誘導は本フィーチャーのスコープ外（Assumptions参照）
- 対象フォルダが非常に大きなリポジトリで`/init`の完了に数分かかる場合はどうなるか? → 他の手順と同様タイムアウト時間内であれば待機し、超過した場合は失敗として扱われる
- 前回の実行で`/init`は成功しCLAUDE.mdは生成されたが、直後のコミットが失敗して未コミットのまま残っている場合、再実行するとどうなるか? → CLAUDE.mdが既に存在するため本手順全体をスキップする。未コミットのCLAUDE.mdを揃えるのは利用者の手動対応に委ねる（Assumptions参照）
- 「Git 初期化と初回コミット」（手順5）が失敗した場合、本手順（手順6）はどうなるか? → 既存のFR-012と同じ仕組みにより「スキップ（前提未達）」として扱われる

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-1301**: システムは、既存の5手順に続く6番目の導入手順として「CLAUDE.md の生成とコミット」を追加しなければならない。既存5手順の実行順序・依存関係は変更しない
- **FR-1302**: 手順6は「Git 初期化と初回コミット」（手順5）に依存し、手順5が失敗した場合は既存のFR-012の仕組みにより「スキップ（前提未達）」として扱わなければならない
- **FR-1303**: 手順6の実行前に、対象フォルダ直下にCLAUDE.mdが既に存在するかを確認しなければならない。存在する場合は生成・コミットのいずれも行わずスキップしなければならない
- **FR-1304**: CLAUDE.mdが存在しない場合、システムは対象フォルダをカレントディレクトリとしてClaude Code CLIを非対話・確認スキップモードで実行し、`/init`を実行してCLAUDE.mdを生成させなければならない
- **FR-1305**: `/init`の実行が終了コード0で完了した後、対象フォルダ直下にCLAUDE.mdが実際に生成されていることを確認しなければならない。コマンドは成功したがCLAUDE.mdが存在しない場合は手順6を失敗として扱わなければならない
- **FR-1306**: CLAUDE.mdの生成を確認できた場合、CLAUDE.md**のみ**をステージし、"CLAUDE.md を追加" というメッセージでコミットしなければならない。他の未コミット変更を巻き込んではならない
- **FR-1307**: Claude Code CLIがPATH上に見つからない場合、他の手順と同じ様式（コマンド名を含む「見つかりません」という理由）で失敗として扱わなければならない
- **FR-1308**: `/init`の実行またはコミットが失敗・タイムアウトした場合、手順6のみを結果一覧に「失敗」として表示すればよく、それより前の手順（Git初期化を含む）の結果を取り消してはならない
- **FR-1309**: 手順6の実行は既存の`ProcessRunner`経由で行い、PATHの再読み込み（009）・タイムアウト監視（008）の仕組みをそのまま利用しなければならない。新規の実行経路を追加してはならない
- **FR-1310**: 手順6のタイムアウトは、`/init`がLLM呼び出しを伴い実行時間が変動しうることを踏まえ、他の手順より十分に長い時間を設定しなければならない
- **FR-1311**: 完了案内（`ShowCompletionGuide`）から、012で追加した「`/init`を実行してCLAUDE.mdを生成する」「生成されたCLAUDE.mdをコミットする」の2手順の文言を削除し、残りの手順の番号を1から振り直さなければならない
- **FR-1312**: 完了案内の見出し・残りの手順文言（VS Codeを開く、テスト方針決定と憲章制定、`/init`再実行）は、番号以外の文言を変更してはならない

### Key Entities（主要エンティティ）

- **SetupStep（既存、拡張）**: 新しい`StepId`（例: CLAUDE.mdの生成とコミット）を1件追加する。既存の構造（`displayName`・`dependsOn`・`result`・`reason`）は変更しない

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-1301**: 利用者は「生成」を1回実行するだけで、SDD化に加えてCLAUDE.mdの生成とコミットまで完了できる。追加の手動操作（VS Codeを開いて`/init`を打つ、コミットする）は不要になる
- **SC-1302**: 手順6が失敗しても、それより前の5手順の結果表示・対象フォルダの状態には影響が無く、結果一覧に6手順分の結果が表示される
- **SC-1303**: 完了案内・結果一覧は、起動直後の大きさのまま全文が読める（006 FR-504・FR-504a・FR-507aの水準を維持する）
- **SC-1304**: 001〜012で合格していた検証項目（SDD化の完走、再実行での全手順スキップ、未選択ガード、案内の複写、リサイズ追従、列幅追従、タイトルバーの色）がすべて再現する

## Assumptions（前提事項）

- 対象マシンには認証済み（ログイン済み）のClaude Code CLIが導入されていることを前提とする。未認証の場合、手順6は失敗として扱われるが、自動ログイン・認証誘導は本フィーチャーのスコープ外とする
- `/init`の実行には、対象フォルダ内でのファイル作成・編集をノンストップで許可する実行モードを用いる。これは対象フォルダに限定された操作であり、対象フォルダは利用者が明示的に選択したものである
- CLAUDE.mdが既に存在する場合、その内容の正しさや最新性は問わずスキップする。これは既存の他手順（例: `.specify`と`.claude`が存在すればスキップする）と同じ「存在すれば完了済みとみなす」設計に合わせたものである
- 生成直後のコミットが何らかの理由で失敗し、CLAUDE.mdが未コミットのまま残った場合、次回実行時は「既に存在する」としてスキップされる。この場合の解消（未コミットのCLAUDE.mdを手動でコミットする）は利用者に委ねる
- 006 FR-507aの見積もり表によれば、結果一覧は現在5行分の内容に対し7行分（158px）の高さの余裕があり、6行目を追加しても`.rc`の寸法変更は不要と見込まれる（実装時に静的テストで裏付ける）
- 完了案内の手順が5行から3行へ減ることにより、012で拡張した案内欄の高さ（61 DLU）にはさらに余裕ができる。文言が短くなったことを理由に寸法を縮小する必要はない（縮小しなくても006 FR-504等の要件は引き続き満たされる）
