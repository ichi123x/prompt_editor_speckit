# Phase 1 Data Model: 失敗理由が装飾バナーに埋もれて見えなくなる問題を解消する

**Feature**: [spec.md](./spec.md) | **Date**: 2026-09-13

本フィーチャーは新しい永続データエンティティを導入しない。以下は`Brief()`が呼ばれるたびにその場で
計算され、どこにも保存されない文字列変換規則である（[research.md](./research.md) R-1102〜1103）。

## 失敗理由の整形規則（`Brief(output, maxLength)` 呼び出しのたびに再計算）

| 手順 | 内容 |
|---|---|
| 1. 行分割 | `output`を`\r\n`・`\n`で行に分割する |
| 2. 行ごとの装飾除去と分類 | 各行からUnicode Box Drawing（U+2500〜U+257F）・Block Elements（U+2580〜U+259F）の範囲に該当する文字を取り除いてTrimし、可視文字が残れば「内容行」、残らなければ「空行」に分類する |
| 3. 段落へのグループ化 | 内容行を連結して段落を作る。空行が1行だけなら区切りとみなさず内容行として連結を続ける。**空行が2行以上連続した場合にのみ**そこまでを1つの段落として確定し、次の段落を開始する |
| 4. 空チェック（フォールバック） | 段落が1つも無い（内容行が皆無だった）場合、`output`を`\r\n`・`\n`・タブのみ半角スペースに正規化した文字列を対象に、既存どおり先頭から`maxLength`文字を切り詰めて返す（FR-1103） |
| 5. 最後の段落の採用と切り詰め | 段落が1つ以上あれば**最後の段落**（各行を半角スペースで連結したもの）を採用する。その長さが`maxLength`以下ならそのまま返し、超える場合は**その段落の先頭から**`maxLength`文字を切り詰め、末尾に省略を示す記号を付けて返す |

この変換はステートレスであり、`Brief()`の呼び出し間で保持される状態はない。既存の5箇所の呼び出し元
（`RunInstallUv`・`RunInstallSpecify`・`RunInitSpecKit`・`RunInitGit`内の各失敗分岐）は、この関数の
戻り値（`CString`）をそのまま`Finish()`の理由文字列として使う点も変わらない。

**実機データでの実測値**（[research.md](./research.md) R-1102）: `specify init`の実際の失敗出力
（装飾除去前2236文字）に本規則を適用すると、3つの段落（251文字・99文字・214文字）に分割され、
最後の段落（214文字、Agent Detection Errorボックスの内容）が採用され、160文字への切り詰め後も
「claude not found」という診断上重要な文字列が結果に含まれることを確認した。
