# Feature Specification: 失敗理由が装飾バナーに埋もれて見えなくなる問題を解消する

**Feature Branch**: `011-fix-error-message-truncation`

**Created**: 2026-09-13

**Status**: Implemented

**Input**: User description: "外部コマンド(specify init等)が失敗した際、結果一覧の「内容」欄に表示される失敗理由が、出力先頭を一定文字数で切り詰めるBrief()の実装により、コマンドが出力する装飾的なバナー(罫線・ブロック文字によるロゴ等)だけで文字数予算を使い切ってしまい、肝心の実際のエラーメッセージ(例: \"claude not found\"のようなAgent Detection Errorの本文)が一切ユーザーに見えなくなる問題を修正する。失敗理由の抽出方法を改善し、装飾的な先頭部分に埋もれてしまう場合でも、実際に診断の役に立つエラー本文がユーザーに見えるようにする。"

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 失敗理由から実際のエラー内容を読み取れる (Priority: P1)

SDD化を実行したユーザーは、いずれかの手順が失敗した際、結果一覧の「内容」欄に、その失敗を診断できる具体的なエラーメッセージが表示されることを期待する。外部コマンドが出力する装飾的なバナーやロゴなど、診断に無関係な出力に埋もれて実際のエラー内容が見えなくなってはならない。

**Why this priority（この優先度である理由）**: 008〜010で実行時のハング・PATH関連の不具合を解消した結果、実機で初めて顕在化した問題である。手順4（Spec Kit足場配置）が実際には「claude CLIが見つからない」という具体的な理由で失敗していたにもかかわらず、結果一覧には診断に使えない装飾文字列しか表示されず、ユーザーが自力で原因を特定できなかった。SDD化ツールとしての実用性を大きく損なう。

**Independent Test（独立したテスト方法）**: 装飾的なバナー（罫線・ブロック文字によるロゴ等）を出力してから具体的なエラーメッセージを出力し、非ゼロ終了する外部コマンドを手順に見立てて実行し、結果一覧の「内容」欄に実際のエラーメッセージが含まれることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） 外部コマンドが装飾的なバナーの後に具体的なエラーメッセージを出力して失敗する、**When**（動作） その手順が実行される、**Then**（結果） 結果一覧の「内容」欄には、そのエラーメッセージの内容が読み取れる形で含まれる。
2. **Given**（前提） 外部コマンドが装飾やバナーを出力せず、短い具体的なエラーメッセージのみを出力して失敗する（従来の失敗パターン）、**When**（動作） その手順が実行される、**Then**（結果） 結果一覧の「内容」欄には従来どおりそのエラーメッセージが表示される（回帰がない）。

---

### Edge Cases（エッジケース）

- 出力全体が装飾的な内容のみで、診断に有用と考えられるエラーメッセージに該当する部分が全く無い場合、既存の「出力先頭を切り詰めて表示する」動作にフォールバックする。
- 出力が非常に長い場合でも、結果一覧に表示する分量の上限は既存のレイアウト制約（006 研究成果）を超えない。
- 出力に日本語と英語が混在する場合（uv・specify・git等、ツールによって混在しうる）、いずれの言語のメッセージも正しく表示される。

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-1101**: システムは外部コマンドが失敗した際、結果一覧に表示する失敗理由として、出力の中から診断に有用と考えられるエラーメッセージ部分を優先的に抽出しなければならない。
- **FR-1102**: 抽出処理は、既存の「出力の先頭から一定文字数を切り詰める」方式のみに頼ってはならない。装飾的な内容（罫線・ブロック文字等）が出力の先頭を占める場合でも、実際のエラー内容が表示から失われてはならない。
- **FR-1103**: 抽出に該当する内容が見つからない場合は、既存の「出力先頭を切り詰めて表示する」動作にフォールバックしなければならない（常に何らかの理由文字列を表示する）。
- **FR-1104**: 表示する理由文字列の長さは、既存の結果一覧の列幅・レイアウト制約（006の成果）を超えてはならない。
- **FR-1105**: 本修正は結果一覧に表示される「失敗理由」の抽出方法のみを対象とし、外部コマンドの実行方法・タイムアウト・成否判定（008・009の成果）や、PATH解決（009・010の成果）には影響を与えてはならない。

### Key Entities（主要エンティティ） *(データが関わる機能の場合に記載)*

N/A（本機能は失敗理由の文字列抽出ロジックの修正であり、新たな永続データエンティティを導入しない）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-1101**: 装飾的なバナーの後に具体的なエラーメッセージを出力して失敗する外部コマンドの実行結果について、100%のケースで結果一覧の「内容」欄からそのエラーメッセージを読み取れる。
- **SC-1102**: 従来型の短い失敗メッセージ（装飾なし）を出力する外部コマンドでは、修正前と同じ表示になる（回帰がない）。
- **SC-1103**: 修正後も結果一覧の列幅にレイアウト崩れが生じない。

## Assumptions（前提事項）

- 診断に有用な部分を優先的に抽出する具体的な方法（例: 特定のキーワードを含む行を優先する等）は`/speckit-plan`で決定する技術判断であり、本specはその選定を指定しない。
- 対象は結果一覧に表示される「内容」列の文字列のみであり、失敗時の出力全文をログファイルへ保存する、詳細表示用のUIを新設する等、新たな仕組みの追加はスコープ外とする（原則III YAGNI）。
- 表示する理由文字列の長さの上限は、既存の切り詰め処理（008以前から存在する`Brief()`）が使っている値を踏襲し、本フィーチャーでは変更しない。
- ビルド構成はDebugでよい（008〜010に引き続きユーザー指示を踏襲）。
