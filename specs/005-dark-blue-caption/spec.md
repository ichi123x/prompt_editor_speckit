# Feature Specification: タイトルバーを濃い青にする

**Feature Branch**: `005-dark-blue-caption`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "ダイアログのタイトルバー（キャプション領域）の色を濃い青色にする。対象は「SDDプロジェクトのベース作成ツール」のメインダイアログ。現在は Windows の既定色（白／システム設定色）で表示されており、他のアプリと見分けがつきにくい。濃い青にすることで、このツールのウィンドウであることが一目で分かるようにする。タイトル文字が背景に埋もれて読めなくならないこと。Windows 11 でのみ着色できれば十分で、着色できない環境では既定の外観のまま動作し続けること（着色の失敗がアプリの起動や動作を妨げないこと）。ダイアログのサイズ・配置・既存のコントロールや機能（004 までのリサイズ追従を含む）は一切変更しない。"

## 001〜004 との関係

本フィーチャーは**ウィンドウの外枠の見た目だけ**を変える。クライアント領域の中身（コントロールの構成・配置・追従方針・処理の内容）には一切触れない。したがって 001〜004 の要件を置き換えるものは無く、すべてそのまま有効である。

| 既存の要件 | 本フィーチャーでの扱い |
|---|---|
| 001 FR-001〜FR-013a（SDD化の5手順、検証チェーン） | 変更しない |
| 002 FR-101〜FR-112（種別選択の廃止、`.gitignore` 統合、案内表示） | 変更しない |
| 003 FR-201〜FR-211（診断機能の廃止） | 変更しない |
| 004 FR-301〜FR-311（リサイズ追従、最小サイズ） | 変更しない |

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 開いているウィンドウの中からこのツールを見つける (Priority: P1)

利用者は Visual Studio・エクスプローラー・ターミナルなど複数のウィンドウを開いたまま作業している。その中からこのツールのウィンドウを探すとき、現在はタイトルバーが他のアプリとまったく同じ既定色のため、タイトルの文字を1つずつ読まないと見分けられない。タイトルバーが濃い青で塗られていれば、**文字を読まずに色だけで**目的のウィンドウに手を伸ばせる。

**Why this priority（この優先度である理由）**: 本フィーチャーの目的そのもの。これ1つで価値が完結し、他のストーリーは無くても成立する。

**Independent Test（独立したテスト方法）**: アプリを起動し、他のアプリのウィンドウと並べて、タイトルバーの色だけで区別できることを目視で確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** アプリを起動した直後、**When** ウィンドウのタイトルバーを見る、**Then** 濃い青で塗られている
2. **Given** 濃い青のタイトルバー、**When** タイトル文字「SDDプロジェクトのベース作成ツール」を読む、**Then** 背景に埋もれず判読できる
3. **Given** 他のアプリのウィンドウを前面にしてこのツールが非アクティブになった状態、**When** タイトルバーを見る、**Then** 引き続き濃い青のままで、探す手がかりとして働く
4. **Given** 濃い青のタイトルバー、**When** 閉じる・最小化・最大化の各ボタンを見る、**Then** どこにあるか分かり、押せる

---

### User Story 2 - 着色できない環境でも今までどおり使える (Priority: P2)

このツールは Windows 11 で使うことを想定しているが、それより古い Windows で起動される可能性がある。着色の仕組みが使えない環境で、着色に失敗したせいでアプリが起動しない・エラーが出る・操作できない、といったことがあってはならない。**色が付かないだけで、ツールとしては何も変わらず使える**必要がある。

**Why this priority（この優先度である理由）**: 見た目の改善のために本来の機能を失うのは本末転倒。ただし US1 が達成されていれば主目的は果たせているため P2。

**Independent Test（独立したテスト方法）**: 着色が効かない状況を作った状態でアプリを起動し、エラーが出ず、既定の外観のまま5手順の実行まで通常どおり行えることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** 着色の仕組みが使えない環境、**When** アプリを起動する、**Then** エラーメッセージも警告も出ず、ウィンドウが通常どおり表示される
2. **Given** 着色されなかったウィンドウ、**When** 対象フォルダを選んで「生成」を押す、**Then** 5手順が最後まで実行され、結果一覧と案内が通常どおり表示される
3. **Given** 着色されなかったウィンドウ、**When** ウィンドウの端をドラッグしてサイズを変える、**Then** 004 の追従がそのまま働く

---

### Edge Cases（エッジケース）

- **ウィンドウを最大化したとき**: タイトルバーの高さや描画のされ方が変わるが、色は濃い青のままでなければならない
- **最小化してタスクバーから戻したとき**: 復帰後も濃い青が保たれていなければならない。復帰のたびに色が抜けるようでは目的を果たさない
- **利用者が Windows のライトモード／ダークモードを切り替えたとき**: どちらのモードでも濃い青のままであること。モードによって色が変わると、探す手がかりとして安定しない
- **利用者が Windows の「アクセントカラーをタイトルバーに表示する」設定を有効／無効にしているとき**: どちらの設定でも本ツールの色が優先されること
- **メッセージボックスや「参照...」のフォルダ選択ダイアログを開いたとき**: これらは本ツールが作るウィンドウではないため着色の対象外。着色されていなくても不合格としない
- **バージョン情報ダイアログ（「MFCApplication1 について」）**: 本フィーチャーのスコープ外。着色されていなくても不合格としない

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-401**: メインダイアログのタイトルバー（キャプション領域）は、**濃い青**で塗られていなければならない
- **FR-402**: 濃い青は**ネイビー `#1F3864`（R31 G56 B100）**とする。落ち着いた紺色であり、主張しすぎず長時間の作業でも目が疲れにくい
- **FR-403**: タイトル文字は、濃い青の背景の上で判読できる色で表示されなければならない。背景と近い色になって読めなくなってはならない
- **FR-404**: 着色はウィンドウが表示される時点で適用されていなければならない。起動後に一瞬既定色が見えてから塗り替わる、といった見え方をしてはならない
- **FR-405**: ウィンドウが非アクティブになっても、濃い青のままでなければならない
- **FR-406**: 最大化・最小化・復帰・サイズ変更のいずれを行っても、濃い青が保たれなければならない
- **FR-407**: Windows のライトモード／ダークモードのどちらでも、濃い青でなければならない
- **FR-408**: 着色が適用できない環境では、**何も起こらなかったかのように**既定の外観で表示され、アプリは通常どおり動作しなければならない。エラーメッセージ・警告・ログの表示をしてはならない
- **FR-409**: 着色の適用に失敗しても、アプリの起動・5手順の実行・リサイズ追従を妨げてはならない
- **FR-410**: ダイアログのサイズ、コントロールの構成・位置・大きさ、および 001〜004 の機能は一切変更してはならない
- **FR-411**: 着色の対象はメインダイアログ1枚のみとする。メッセージボックス、フォルダ選択ダイアログ、バージョン情報ダイアログは対象外とする
- **FR-412**: 追加・変更した各箇所には、対応する FR 番号をコメントで記載しなければならない（憲章 原則IV）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-401**: 複数のアプリのウィンドウが並んだ状態で、利用者はタイトルの文字を読まずに、**色だけで**このツールのウィンドウを特定できる
- **SC-402**: タイトル文字が判読できる。背景 `#1F3864` と文字色の明るさの比（コントラスト比）が **4.5:1 以上**であること。これは小さな文字でも読めるとされる一般的な下限であり、白文字なら約 11.5:1 で十分に上回る
- **SC-403**: アクティブ／非アクティブ、最大化／通常／最小化からの復帰、ライトモード／ダークモードの**すべての組み合わせで色が変わらない**
- **SC-404**: 着色できない環境で、001〜004 の合格項目がすべて再現する（SDD化の完走、再実行で全手順スキップ、未選択ガード、案内のコピー、リサイズ追従、最小サイズ）
- **SC-405**: ビルド警告が0件で、コード分析の指摘が0件

## Assumptions（前提事項）

- **対象は Windows 11**。利用者の環境は Windows 11 Pro であり、そこで着色できれば目的は達成される。それより古い Windows は「着色されないが問題なく動く」ことのみを保証する
- **タイトル文字は明るい色にする**。濃い青の背景に対して読めるようにするには文字を明るくする必要がある。FR-403 の判読性は、文字を白に近い明るい色にすることで満たすものと想定する
- **非アクティブ時も同じ濃い青**とする。Windows の標準的なアプリは非アクティブ時にタイトルバーを淡くするが、本フィーチャーの目的は「探しやすさ」であり、非アクティブのときこそ探す場面が多い。色を変えないほうが目的に合う
- **ウィンドウの枠線・ボタンの色は変更しない**。閉じる・最小化・最大化のボタンは Windows が描くものをそのまま使う
- **色の設定項目は設けない**。利用者が色を選べるようにする要求は現時点で無いため、色は固定とする（憲章 原則III のYAGNI）
- **クライアント領域（ダイアログの中身）の背景色は変更しない**。今回変えるのはタイトルバーのみである
