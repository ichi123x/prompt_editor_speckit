# Feature Specification: リポジトリ登録の要否を選択できるようにする

**Feature Branch**: `016-repo-registration-toggle`

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "生成ボタンの右側に、"リポジトリの登録："ラベルを作成し、OK, NGのラジオボタンを配置する。デフォルトは、"する"を選択する。OKの場合は、Git初期化と初回コミットの処理、CLAUDE.mdの生成とコミットの処理を実行する。NGの場合、Git初期化と初回コミットの処理、CLAUDE.mdの生成とコミットの処理を実行しない。ただし、NGの場合でも、CLAUDE.mdは生成される。そのため、処理とメッセージは、Git初期化と初回コミット、OKの場合は、CLAUDE.mdの生成とコミット、NGの場合は、CLAUDE.mdの生成になる。"

**001・013との関係**: 001は「Git 初期化と初回コミット」を手順5として定義し、013はそれに依存する形で「CLAUDE.md の生成とコミット」を手順6として自動化した。本フィーチャーはこの2手順の実行可否を利用者が選べるようにする。手順6の「生成」部分（`claude --print /init ...`の実行）は手順5の成否によらず独立して実行できるようにし、「コミット」部分のみを利用者の選択でオン/オフする。手順1〜4（uv・specify CLI・VS Code拡張の導入、Spec Kit足場の配置）は変更しない。

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - Gitに触れさせずにSpec Kit足場とCLAUDE.mdだけを用意する (Priority: P1)

利用者は、対象フォルダをまだGitで管理したくない（別の方法で管理する予定がある、あるいはリモートに公開する前に内容を確認したい等）。「リポジトリの登録：」を「NG」に切り替えてから「生成」を押すと、uv・specify CLI・VS Code拡張の導入とSpec Kit足場の配置、CLAUDE.mdの生成は行われるが、対象フォルダへのGit初期化・コミットは一切行われない。

**Why this priority（この優先度である理由）**: 現状はGit初期化と初回コミットが必ず実行されるため、まだGit管理を始めたくない利用者がこのツールを使えない。これを解消することが本フィーチャーの主目的である。

**Independent Test（独立したテスト方法）**: 空の対象フォルダに対し「NG」を選択して生成し、フォルダに`.git`が作成されていないこと、`CLAUDE.md`は生成されていること、結果一覧の該当2行の表示がFR-1605・FR-1606の通りであることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** 「リポジトリの登録：」が「NG」に切り替えられている、**When** 「生成」を押す、**Then** 「Git 初期化と初回コミット」の行はスキップとして表示され、対象フォルダに`.git`は作成されない
2. **Given** 同上、**When** 生成が完了する、**Then** 「CLAUDE.md の生成」の行が成功として表示され、対象フォルダに`CLAUDE.md`が存在する。ただしコミットは行われない
3. **Given** 同上、**When** 手順1〜4（uv・specify CLI・VS Code拡張・Spec Kit足場）を見る、**Then** これまでと同じ基準で実行される（選択の影響を受けない）

---

### User Story 2 - 何も操作しなければこれまで通りGitまで自動化される (Priority: P2)

既存の利用者は、これまで通りGit初期化・初回コミット・CLAUDE.mdのコミットまで自動で終わらせたい。ラジオボタンを操作せず（既定のまま）「生成」を押すと、001〜015までの動作が変わらず再現される。

**Why this priority（この優先度である理由）**: 既存利用者にとっての破壊的変更を防ぐための回帰確認であり、新規のGit非対応そのもの（US1）よりは優先度が下がる。

**Independent Test（独立したテスト方法）**: ラジオボタンに一切触れずに生成し、001〜015の既存の動的テスト手順がすべて変わらず成立することを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** ダイアログを起動した直後（初期状態）、**When** 「リポジトリの登録：」を見る、**Then** 「OK」が選択されている
2. **Given** 「OK」が選択されたまま、**When** 「生成」を押して完了する、**Then** 「Git 初期化と初回コミット」「CLAUDE.md の生成とコミット」の両方が、これまでと同じ文言・条件で実行される

---

### Edge Cases（エッジケース）

- **対象フォルダが既に別の場所でGit管理されている状態で「NG」を選んだ場合**: 既存の入れ子リポジトリチェック等（001の検証チェーン）は選択に関わらず変更しない。「NG」の選択は新規のGit初期化を行わないという指示であり、既存の検証ロジックには影響しない
- **「NG」を選んだ状態で生成中に選択を変更しようとした場合**: ラジオボタンは処理中も操作できる。選択は「生成」を押した瞬間にコピーされるため、実行中の処理には影響しない（FR-1608、2026-09-17実機確認により無効化しない方針に改訂）
- **「NG」を選んだ場合の完了案内の文言**: 既存の完了案内（`IDC_STATIC_GUIDE`）はGit固有の内容を含まないため、文言自体の変更は必須ではない。ただし、Git初期化が行われなかった事実が結果一覧から読み取れることで足りるものとする

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-1601**: システムは、ダイアログの「生成」ボタンの右側に「リポジトリの登録：」ラベルと、「OK」/「NG」の2択のラジオボタンを配置しなければならない。既定の選択は「OK」でなければならない（2026-09-17 Clarification）
- **FR-1602**: 「OK」が選択された状態で生成を実行した場合、「Git 初期化と初回コミット」「CLAUDE.md の生成とコミット」を含め、001〜015の動作のまま実行しなければならない
- **FR-1603**: 「NG」が選択された状態で生成を実行した場合、「Git 初期化と初回コミット」の手順（`.gitignore`の生成・`git init`・初回コミットを含む）を実行してはならない
- **FR-1604**: 「NG」が選択された場合でも、CLAUDE.mdの生成（`claude --print /init ...`の実行）は実行しなければならない。ただし、生成したCLAUDE.mdをコミットする処理（`git add` / `git commit`）は実行してはならない
- **FR-1605**: 結果一覧の該当行は、選択に応じて次のように表示しなければならない：「OK」の選択時は項目名「CLAUDE.md の生成とコミット」・完了時内容「CLAUDE.md を生成し、コミットしました。」、「NG」の選択時は項目名「CLAUDE.md の生成」・完了時内容「CLAUDE.md を生成しました。」
- **FR-1606**: 「NG」が選択された場合、結果一覧の「Git 初期化と初回コミット」の行は、実行せずスキップした旨とその理由（利用者が登録しない選択をしたこと）を「結果」列・「内容」列に表示しなければならない
- **FR-1607**: 手順1〜4（uv・specify CLI・VS Code拡張の導入、Spec Kit足場の配置）は、ラジオボタンの選択に関わらず従来通り実行しなければならない
- **FR-1608**（2026-09-17改訂）: ラジオボタンは、生成処理中（ワーカースレッド実行中）も無効化せず、操作可能なままにしなければならない。選択は「生成」押下時に一度だけ読み取ってワーカーへ渡すため、処理中に選択を変えても実行中の処理には影響しない。実機確認の結果、無効化（グレーアウト）は不要と判断した
- **FR-1609**: 新しいコントロールの配置は、001〜015で確立された機能（検証チェーン、リサイズ追従、タイトルバー色、DPI対応の列margin）を破壊してはならない
- **FR-1610**: 追加・変更した各箇所には、対応するFR番号をコメントで記載しなければならない（憲章 原則IV）
- **FR-1611**: 本フィーチャーで行う判定（新規コントロールの配置が既存レイアウトを圧迫しないこと等）は、目視ではなく実測に基づかなければならない（憲章 原則V）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-1601**: 利用者は追加操作なし（既定のまま）で、これまで通りリポジトリ登録ありでSDD化を完了できる
- **SC-1602**: 利用者は「NG」を選択するだけで、対象フォルダへのGit初期化を一切行わずにSpec Kit足場とCLAUDE.mdを配置できる
- **SC-1603**: 「NG」を選択した場合、結果一覧の表示だけから「Gitへの登録は行われなかったこと」と「CLAUDE.mdは生成されたこと」の両方を読み取れる
- **SC-1604**: 新しいコントロールの追加後も、001〜015で合格していた検証項目が開発機環境（115 DPI）ですべて再現する
- **SC-1605**: ビルド警告が0件で、コード分析の指摘が0件

## Assumptions（前提事項）

- ラジオボタンの選択状態は起動のたびに既定（「OK」）にリセットされ、永続化しない（対象フォルダのパス欄も同様に永続化されないことと整合させる）
- 選択に関わらず、書き込み権限・マーカー・足場の中途半端・入れ子リポジトリといった既存の検証チェーン（001）は変更しない
- 「NG」を選んだ場合の完了案内（`IDC_STATIC_GUIDE`）の文言は、現行の文言がGit固有の内容を含まないため、変更を必須としない
- 新規追加する文字列（ラベル「リポジトリの登録：」、ラジオボタンの表示文字列、行の項目名・内容メッセージ）はすべて日本語とする（憲章 原則II）
