# Feature Specification: 完了案内にCLAUDE.mdのコミット手順を追加する

**Feature Branch**: `012-guide-claude-md-commit`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "SDD化完了時にアプリが表示する案内文（次にClaude Codeで行うべき手順の一覧）に、/initを実行してCLAUDE.mdを生成した直後に、それをGitへコミットする手順が抜けている問題を修正する。参考にしたセットアップ手順書(SpecKitVSCodesetup.pdf 手順08)では、/init実行の直後に git add -A / git commit -m \"CLAUDE.md を追加\" を行うことになっており、これをコミットしないまま次の手順(テスト方針の決定・/speckit-constitution)に進むと、生成されたCLAUDE.mdが未コミットのまま放置されうる。案内文に、/init実行後のコミット手順を追加する。"

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 完了案内から生成直後のCLAUDE.mdをコミットする手順が分かる (Priority: P1)

SDD化を完了させたユーザーは、表示された案内に従って`/init`を実行しCLAUDE.mdを生成した直後、そのファイルをGitへコミットする手順も同じ案内の中で示されることを期待する。手順が抜けていると、生成されたCLAUDE.mdが未コミットのまま、続く「テスト方針の決定」「憲章の制定」といった後続作業に進んでしまう可能性がある。

**Why this priority（この優先度である理由）**: 参照した導入手順書（SpecKitVSCodesetup.pdf 手順08）では、`/init`実行の直後にコミットする工程が明記されている。現在の完了案内にはこの工程が欠けており、ユーザーがこの手順書を別途参照しない限りコミット漏れに気づけない。案内文はSDD化後に次の手順を伝える唯一の手段（001 FR-011）であるため、抜けはそのまま実運用上のリスクになる。

**Independent Test（独立したテスト方法）**: SDD化を成功させ、表示される完了案内の文言を確認するだけで検証できる。「`/init`を実行しCLAUDE.mdを生成する」という手順の直後に、生成されたCLAUDE.mdをGitへコミットする手順が示されていることを目視で確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） SDD化のすべての手順が成功し完了案内が表示された状態、**When**（動作） 案内文を確認する、**Then**（結果） 「`/init`を実行しCLAUDE.mdを生成する」手順の直後に、生成されたCLAUDE.mdをGitへコミットする手順が示されている。
2. **Given**（前提） コミット手順が追加され手順数が増えた案内文、**When**（動作） 憲章制定後のCLAUDE.md再生成（既存の手順）を確認する、**Then**（結果） 既存の各手順が伝えていた内容（フォルダを開く／テスト方針の決定と憲章制定／憲章反映後の`/init`再実行）はそのまま維持されている。

---

### Edge Cases（エッジケース）

- いずれかの手順が失敗した場合に表示される案内文（「一部の手順が失敗しました。一覧の「内容」欄で理由を確認してください。」）は、本フィーチャーの対象外であり変更しない。この完了案内（`/init`以降の手順一覧）は、すべての手順が成功した場合にのみ表示される。
- 対象フォルダで手順5（Git初期化・初回コミット）自体が何らかの理由で「スキップ」（既にコミット済みで変更なし）だった場合でも、`/init`実行後に新たにCLAUDE.mdが生成されればそれは未コミットの変更になるため、コミット手順の案内は変わらず有効である。

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-1201**: システムは、SDD化が成功した場合に表示する完了案内において、「`/init`を実行しCLAUDE.mdを生成する」手順の直後に、生成されたCLAUDE.mdをGitへコミットする手順を追加しなければならない。
- **FR-1202**: コミット手順の追加に伴い、既存の各手順（フォルダを開く、`/init`実行、テスト方針決定と憲章制定、憲章反映後の`/init`再実行）が伝えていた内容を変更してはならない。手順番号は追加に伴い振り直してよい。
- **FR-1203**: 本修正はSDD化成功時の完了案内文にのみ適用し、失敗時の案内文やその他のUI文字列に影響を与えてはならない。
- **FR-1204**: 追加するコミット手順の文言は、既存のGit操作の案内（結果一覧に表示されるGit初期化手順の説明）と表現の一貫性を保たなければならない。
- **FR-1205**: 完了案内の行数が増えることで006 FR-507aの定める余裕（案内欄の表示行数の余裕は0行）を超えるため、案内欄（`IDC_STATIC_GUIDE`）の高さを、増えた行数を折り返し1回の吸収込みでスクロールなしに表示できるよう調整しなければならない（006 FR-504・FR-504aの継承）。調整は006が確立した実測に基づく手法（1行あたりの表示高さの実測値を用いた算出、開発機115 DPI基準での確認）を踏襲する。

### Key Entities（主要エンティティ） *(データが関わる機能の場合に記載)*

N/A（本機能は既存の案内文字列の追記であり、新たな永続データエンティティを導入しない）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-1201**: SDD化がすべて成功した状態で完了案内を表示したとき、100%のケースで「`/init`実行→CLAUDE.mdのコミット」の順に手順が示される。
- **SC-1202**: 追加後の案内文でも、既存の結果一覧・案内表示領域のレイアウトが崩れない（006の成果を踏襲する）。
- **SC-1203**: 起動直後の大きさのまま、完了案内の6行（見出し＋手順5つ）すべてが、フォルダパスの折り返し1回を含めてスクロールなしで表示される（006 FR-504・FR-504aの水準を、行数が1つ増えた状態でも維持する）。

## Assumptions（前提事項）

- コミット手順で使用するコマンド例（`git add -A` / `git commit -m "..."`）は、参照した導入手順書の表記に倣う。コミットメッセージの具体的な文言は`/speckit-plan`で決定する技術判断であり、本specはその選定を指定しない。
- 本フィーチャーはアプリが自動でコミットを実行することを意味しない。あくまで案内文に手順を追記するのみであり、実行は引き続きユーザー（Claude Codeとの対話を通じて）が行う。
- ビルド構成はDebugでよい（008〜011に引き続きユーザー指示を踏襲）。
- 案内欄の高さ調整（FR-1205）に伴い、`MFCApplication1.rc`（ダイアログリソース）も変更対象に含まれる。当初は`MFCApplication1Dlg.cpp`の文字列変更のみを想定していたが、`/speckit-analyze`により006 FR-507aとの矛盾が判明したため、スコープを訂正した。
- 006 FR-508（004のリサイズ追従8方針を変更してはならない）は本フィーチャーでも維持する。案内欄の高さと、それに連動するOKボタン・キャンセルボタンのY座標・ダイアログ全体の高さのみを`.rc`上で調整し、追従方針（`AnchorMode`）自体や`OnSize`/`OnGetMinMaxInfo`のロジックは変更しない（004・006の前例により、初期矩形の変更だけで追従ロジックは自動的に追従するため）。
