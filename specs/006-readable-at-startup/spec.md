# Feature Specification: 起動直後のまま結果と案内が読める

**Feature Branch**: `006-readable-at-startup`

**Created**: 2026-09-10

**Status**: Draft

**Input**: User description: "初期表示のままで結果内容と完了案内が最後まで読めるようにする。現状の2つの問題を直す。(1) 結果一覧の「内容」列が狭く、Git 手順の説明文「Git は初期化済みで、コミットと .gitignore も揃っています。」が右側で切れて読めない。ウィンドウを横に広げれば読めるが、利用者がそれをしないと読めない。(2) 完了案内の欄が3行分の高さしかなく、案内は5行あるため後半2行がスクロールしないと読めない。どちらも「利用者が何もしなくても、起動直後の大きさのまま全文が読める」状態にしたい。004 のリサイズ追従、003 の5手順、005 のタイトルバーの色など既存の機能・見た目は壊さないこと。ダイアログを大きくする場合は最小サイズも連動するため、画面の小さい環境で困らない範囲に収めること。"

## 001〜005 との関係

本フィーチャーは**初期表示の寸法だけ**を変える。手順の内容・検証の順序・メッセージの文言・追従方針・配色には一切触れない。

| 既存の要件 | 本フィーチャーでの扱い |
|---|---|
| 001 FR-001〜FR-013a（SDD化の5手順、検証チェーン） | 変更しない |
| 002 FR-101〜FR-112（`.gitignore` 統合、案内表示の可読性とコピー可能性） | **強化する**（読める範囲を広げる。文言は変えない） |
| 003 FR-201〜FR-211（診断機能の廃止） | 変更しない |
| 004 FR-301〜FR-311（リサイズ追従、最小サイズ） | **追従方針は変更しない**。初期寸法と最小サイズの値のみ変わる |
| 005 FR-401〜FR-412（タイトルバーの着色） | 変更しない |

## 現状の実測値（問題の裏付け）

| 対象 | 現状 | 必要 |
|---|---|---|
| 結果一覧「内容」列の幅 | **212 px** | 下表のとおり |
| 完了案内の欄の高さ | **49 px**（約3行） | 5行 |

「内容」欄に表示されうる文字列の実測幅（`MS UI Gothic` 9pt）:

| メッセージ | 幅 | 結果の種類 |
|---|---|---|
| `uv は導入済みです。` | 128 px | スキップ |
| `Claude Code 拡張は導入済みです。` | 222 px | スキップ |
| `Git を初期化し、初回コミットを作成しました。` | 266 px | 完了 |
| `前提となる手順が失敗したため実行しませんでした。` | 306 px | スキップ（前提未達） |
| `Git は初期化済みで、コミットと .gitignore も揃っています。` | **339 px** | スキップ — 利用者が報告した切れる文字列 |
| `Git初期化はスキップ。コミットすべき変更がありませんでした。` | 351 px | 完了 |
| `uv が見つかりません。インストールして PATH を通してから再実行してください。` | 454 px | 失敗 |
| `Git初期化はスキップ。既存の未コミット変更を検出したため、.gitignore のみをコミットしました。` | **543 px** | **完了** — 全体の最長 |

他の2列に必要な幅も実測した。

| 列 | 最長の文字列 | 必要な幅 |
|---|---|---|
| 項目 | `Git 初期化と初回コミット` | 150 px |
| 結果 | `スキップ（前提未達）` | 122 px |

**現在の比率 40 / 20 / 40 は配分を誤っている。** 「項目」に 212 px、「結果」に 106 px を割り当てているが、実際に必要なのは 150 px と 122 px である。余っている分を「内容」へ回せる。

**現在の 212 px は、最も短い `uv は導入済みです。`（128 px）以外のすべてを切り落としている。** 利用者が報告した 339 px の文字列も、最長の 543 px も読めない。

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 結果の説明を最後まで読む (Priority: P1)

利用者は「生成」を押した後、結果一覧で各手順がどうなったかを確認する。現在は「内容」列が狭く、説明文が右端で切れる。読むにはウィンドウを横に引っ張るか、列の境界をドラッグして広げる必要がある。**起動したままの大きさで、説明文が最後まで読めてほしい。**

**Why this priority（この優先度である理由）**: 結果一覧はこのツールの主たる出力である。何が起きたのかが読めないのは、機能そのものが半分しか届いていないのと同じ。

**Independent Test（独立したテスト方法）**: アプリを起動し、ウィンドウのサイズも列幅も一切変えずに「生成」を実行して、5行すべての「内容」欄が省略記号（`...`）なしで表示されることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** アプリを起動した直後の大きさ、**When** SDD化済みのフォルダで「生成」を押す、**Then** 結果一覧5行の「内容」欄がすべて途中で切れずに読める
2. **Given** アプリを起動した直後の大きさ、**When** 未導入のフォルダで「生成」を押して各手順が「完了」になる、**Then** その説明文も途中で切れずに読める
3. **Given** 起動直後の大きさ、**When** 結果一覧を見る、**Then** 「項目」列と「結果」列の文字も切れていない
4. **Given** 起動直後の大きさ、**When** 結果一覧を見る、**Then** 横スクロールバーが出ていない

---

### User Story 2 - 完了案内を最後まで読む (Priority: P2)

SDD化が完了すると、次に何をすればよいかが5行で案内される。現在は欄の高さが3行分しかなく、**4番目と5番目の行（憲章の制定と `/init` の再実行）がスクロールしないと見えない**。利用者はスクロールバーの存在に気づかないまま「案内は3行で終わり」と誤解しうる。**起動したままの大きさで5行すべてが見えてほしい。**

**Why this priority（この優先度である理由）**: 見えない2行は「テスト方針を決めて憲章を制定する」という、SDD を始めるうえで欠かせない工程である。ただし US1 が直れば結果の把握という主目的は果たせるため P2。

**Independent Test（独立したテスト方法）**: アプリを起動し、サイズを変えずに「生成」を完走させて、案内欄に5行すべてが同時に表示され、縦スクロールバーが操作を要求しないことを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given** アプリを起動した直後の大きさ、**When** SDD化が完了する、**Then** 完了案内の5行すべてが同時に見える
2. **Given** 5行すべてが見えている状態、**When** 案内欄の文字を選択して複写する、**Then** 002 FR-111 のとおり複写できる（可読性の改善が複写を壊していない）
3. **Given** 起動直後の大きさ、**When** 起動時の初期案内（2行）を見る、**Then** これも全文が見える

---

### Edge Cases（エッジケース）

- **最長のメッセージは失敗時のものではない**: 最長は `Git初期化はスキップ。既存の未コミット変更を検出したため、.gitignore のみをコミットしました。`（**543 px**）で、これは**「完了」の結果に付く正常時のメッセージ**である。既存リポジトリで未コミット変更がある状態で「生成」を押すと出る。失敗時の最長（`uv が見つかりません…` 454 px）よりも長い。「正常時は短く、失敗時だけ長い」という思い込みで幅を決めると足りなくなる
- **メッセージは連結されて伸びる**: Git 手順の説明は固定文ではなく、条件に応じて `Git初期化はスキップ。` などが前に足される。単独の文字列だけを測ると最長を見落とす
- **ウィンドウを最小サイズまで縮めたとき**: 初期サイズ＝最小サイズ（004 FR-306）なので、縮めても読める状態が保たれる
- **ウィンドウを広げたとき**: 004 の追従により一覧と案内欄は広がる。列幅も比率で追従する（004 FR-308）。読める状態が壊れてはならない
- **利用者が列の境界を手でドラッグして狭めたとき**: 004 の割り切り（リサイズのたびに既定比率へ戻る）をそのまま踏襲する。本フィーチャーで列幅の手動調整を保持する仕組みは作らない
- **画面の小さい環境**: ダイアログを大きくすると最小サイズも同じだけ大きくなる。小さい画面でウィンドウが画面からはみ出してはならない

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-501**: 起動直後の大きさのまま、結果一覧の「内容」欄に表示される文字列が省略されずに読めなければならない。**保証する範囲は「表示されうるすべてのメッセージ」**とし、失敗時のものも含める。実測での最長は **543 px**（`Git初期化はスキップ。既存の未コミット変更を検出したため、.gitignore のみをコミットしました。`）である
- **FR-502**: 起動直後の大きさのまま、結果一覧の「項目」欄と「結果」欄の文字列が省略されずに読めなければならない
- **FR-503**: 起動直後の大きさのまま、結果一覧に横スクロールバーが現れてはならない
- **FR-504**: 起動直後の大きさのまま、完了案内の5行すべてが同時に表示されなければならない
- **FR-505**: 起動直後の大きさのまま、起動時の初期案内（2行）の全文が表示されなければならない
- **FR-506**: 初期ウィンドウサイズは、**1024x768 の画面の作業領域に収まらなければならない**。タスクバーを考慮し、幅・高さともにその範囲を超えてはならない
- **FR-507**: 最小ウィンドウサイズは、004 FR-306 のとおり初期ウィンドウサイズと同一でなければならない。初期サイズを変えた結果として最小サイズも変わるが、両者が一致する関係は維持する
- **FR-508**: 004 の追従方針8件（`Fixed`・`StretchH`・`AnchorRight`・`StretchBoth`・`AnchorBottomStretchH`・`AnchorBottomRight` の割り当て）を変更してはならない
- **FR-509**: 結果一覧の列幅がウィンドウ幅に追従する仕組み（004 FR-308）を維持しなければならない。比率の値は変更してよい
- **FR-510**: コントロールの構成（8個）を変更してはならない。追加・削除・種類の変更を行わない
- **FR-511**: 表示される文言を変更してはならない。読める範囲を広げるだけであり、メッセージを短く言い換えることで解決してはならない
- **FR-512**: 001〜005 の機能（5手順、検証チェーン、`.gitignore` のべき等な生成、案内の複写、リサイズ追従、タイトルバーの着色）を変更してはならない
- **FR-513**: 追加・変更した各箇所には、対応する FR 番号をコメントで記載しなければならない（憲章 原則IV）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-501**: 利用者は、ウィンドウのサイズ変更も列幅の調整もスクロールも行わずに、結果一覧5行の内容を最後まで読める。**必要な操作は0回**。判定は「各列の幅 ≧ その列に出うる最長文字列の描画幅 + 余白 20 px + 余裕 8 px」をピクセルで比較して行う。余白は実測できない見積もりであり、検査と実装が同じ値を共有するため、余裕を別に確保する
- **SC-502**: 利用者は、スクロールせずに完了案内の5行すべてを読める。**必要な操作は0回**
- **SC-503**: 初期ウィンドウサイズが 1024x768 の作業領域に収まる
- **SC-504**: 001〜005 で合格していた検証項目がすべて再現する（SDD化の完走、再実行で全手順スキップ、未選択ガード、案内の複写、リサイズ追従の8方針、列幅の比率追従、タイトルバーの色）
- **SC-505**: ビルド警告が0件で、コード分析の指摘が0件

## Assumptions（前提事項）

- **文字の大きさは変更しない**。ダイアログのフォントは既定のままとし、文字を小さくして詰め込む方法は採らない。読みにくくなるため
- **列幅の手動調整を保持する仕組みは作らない**。004 の割り切り（リサイズのたびに既定比率へ戻る）をそのまま維持する
- **省略記号やツールチップで補う方法は採らない**。「切れているが、マウスを乗せれば読める」は FR-501 の「利用者が何もしなくても読める」を満たさない
- **想定する最小の画面は 1024x768**。これは現在流通しているノート PC の下限にあたる。実際の開発機は 1920x1080 だが、それを前提にすると狭い画面で破綻する
- **列幅の比率は変更してよい**。現在の 40 / 20 / 40 は「項目」「結果」に必要以上を割り当てているため、実測に基づいて配分し直す。比率を1箇所で定義する仕組み（004 FR-308）はそのまま維持する
- **測定に使うフォントは `MS UI Gothic` 9pt**。ダイアログテンプレートが `DS_SHELLFONT` を指定しており、日本語環境の既定がこれになる
- **「読める」の判定はピクセル幅の比較で行う**。文字列の描画幅が列幅以下であれば省略記号は出ない。目視ではなく実測で判定する（005 で目視判断を誤った経緯による）
