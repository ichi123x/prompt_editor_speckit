## 3. 操作フローの契約（変更後）

### 3.1 「生成」ボタン

001・002 から**変更なし**。5段階の検証チェーンも、その順序も維持する（FR-207）。

```
押下
 ├─ 1. フォルダ未選択？        → 「対象フォルダを選択してください。」で中止
 ├─ 2. 書き込み権限なし？      → 権限不足の案内で中止
 ├─ 3. プロジェクトマーカーなし？ → ウィザードでの作成を促して中止
 ├─ 4. .specify と .claude の一方だけ存在？ → 警告して手動確認を促し中止
 ├─ 5. GitState = NestedUnderParent？ → 入れ子リポジトリの警告
 │
 ├─ 生成・参照ボタンを無効化（2種。診断ボタンは存在しない）
 ├─ 対象フォルダパスをワーカースレッドへコピーして渡す
 ├─ ワーカースレッドを起動し、5手順を順に実行
 └─ 完了通知の受信 → ボタンを有効に戻す → 完了案内を表示
```

### 3.2 削除する操作フロー

001 の「3.3 準備状況を診断ボタン」を**削除**する。

```
✂ 押下
✂  ├─ フォルダ未選択？ → 「対象フォルダを選択してください。」で中止
✂  ├─ 7項目を判定（すべて読み取り専用）
✂  ├─ IDC_LIST_RESULT に7行を表示
✂  └─ IDC_STATIC_GUIDE に未達項目に対する案内を表示
```

これに伴い、001 の FR-020 が定めていた「診断は対象フォルダに一切の書き込みを行わない」という契約も消滅する。**ただし `TargetFolder::IsWritable()` を検証チェーン以外から呼ばない**という設計は維持する。この関数は一時ファイルを作るため、呼び出す場所を増やさない。

### 3.3 実行中に無効化するコントロール（**回帰注意箇所**）

002 では3コントロール（生成・診断・参照）を無効化していた。003 では**診断ボタンのみを取り除き、2コントロールを無効化する**。

| コントロールID | 003 での扱い |
|---|---|
| `IDC_BUTTON_GENERATE` | **無効化する**（二重実行の防止。001 FR-014） |
| `IDC_BUTTON_BROWSE` | **無効化する**（処理中のフォルダ変更を防ぐ） |
| `IDC_BUTTON_DIAGNOSE` | 削除に伴い対象から外す |

**契約（FR-209 / research.md R-204(1)）**: 配列から削除するのは**真ん中の1要素のみ**である。

```cpp
CWnd* controls[] = {
    GetDlgItem(IDC_BUTTON_GENERATE),    // ← 残す
    GetDlgItem(IDC_BUTTON_DIAGNOSE),    // ← 削除
    GetDlgItem(IDC_BUTTON_BROWSE)       // ← 残す
};
```

前後を巻き添えにしてはならない。生成ボタンの無効化は二重実行防止、参照ボタンの無効化は 001 の analyze で HIGH として指摘し追加した項目である。002 の DT-107 と同じ構図の誤りであり、**DT-207 がこれを検出する**。

完了通知の受信時に2コントロールとも有効へ戻す契約（成功・失敗・中断のいずれでも）は変更しない。

`ShowReadinessGuide()` が組み立てていた文字列を削除する。

```
✂ 7項目すべてを満たしています。VS Code の Claude パネルで /speckit-specify を実行して…
✂ 残りの工程は Claude Code との対話が必要です。次の順に進めてください。

`ReadinessChecker` が持っていた7項目の項目名（「ビルドが通る雛形がある」等）と `nextAction` の文言も、ファイルごと削除する。

### 残す表示文字列（**削除禁止**）

**初期表示の案内文**（FR-206）— 002 で種別への言及を取り除いた版をそのまま使う。診断への言及は元から含まれていないため、変更は不要である。

```
対象フォルダを選び、「生成」を押してください。
対象のプロジェクトは、あらかじめ Visual Studio 2022 などのウィザードで作成し、
そのフォルダに配置しておいてください。
```

**完了時の案内**（FR-205 / ST-204）— 001 から内容を変更しない。

```
Spec Kit の導入が完了しました。次の手順は Claude Code との対話が必要です。
 1. VS Code で {対象フォルダ} を開く（.specify と .claude が直下に見えるフォルダ）
 2. Claude パネルで /init を実行し、CLAUDE.md を生成する
 3. テスト方針を決め、/speckit-constitution で憲章を制定する
 4. /init を再実行し、憲章を反映した CLAUDE.md に更新する

**取り違え注意**: `ShowCompletionGuide()`（残す）と `ShowReadinessGuide()`（削除）は名前が似ており、宣言も隣接している。前者を消すと SDD化の後に次の手順が一切案内されなくなる。002 の FR-110〜112 で読みやすさとコピー可能性を確保したばかりの機能であり、**DT-205 がこれを検出する**。
