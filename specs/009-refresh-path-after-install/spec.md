# Feature Specification: 新規インストール直後のPATH未反映を解消する

**Feature Branch**: `009-refresh-path-after-install`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "SDD化の実行中に外部ツール(uv・specify CLI等)を新規インストールした直後、同一プロセス内では環境変数PATHの更新が反映されず、後続の手順がインストール直後のコマンドを「見つかりません」として失敗する問題を修正する。手順の合間にレジストリ(ユーザー環境変数・システム環境変数)からPATHを読み直し、現在のプロセスのPATHへ反映することで、アプリを再起動しなくても新規インストールしたツールを後続の手順から使えるようにする。"

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - 新規インストールしたツールを同一実行内の後続手順から使える (Priority: P1)

uvやspecify CLIが未導入の環境で「生成」を実行したユーザーは、手順の途中でこれらのツールが新規にインストールされた場合、続く手順がそのツールを正しく検出し、アプリを再起動しなくても最後まで処理が進むことを期待する。

**Why this priority（この優先度である理由）**: 008でwingetの対話プロンプト起因のハングを解消した結果、初めて実機で顕在化した問題である。この問題が残る限り、uv・specify CLIのいずれかが未導入の環境では、両方とも新規インストールに成功しても後続の手順が「見つかりません」で失敗し、SDD化ツールとして初回実行だけで完走できない。

**Independent Test（独立したテスト方法）**: uvとspecify CLIの両方が未導入の環境で対象フォルダを選択し「生成」を実行するだけで検証できる。手順1（uv導入）が成功した直後の手順2（specify CLI導入）が「uvが見つかりません」で失敗しないこと、手順2の成功直後の手順4（Spec Kit足場配置）が「specifyが見つかりません」で失敗しないことを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） uvが未導入の環境、**When**（動作） 「生成」を実行し手順1でuvが新規にインストールされる、**Then**（結果） 続く手順2はインストールされたuvを検出でき、「uvが見つかりません」という失敗にならない。
2. **Given**（前提） specify CLIが未導入の環境、**When**（動作） 手順2でspecify CLIが新規にインストールされる、**Then**（結果） 続く手順4はインストールされたspecifyを検出でき、「specifyが見つかりません」という失敗にならない。

---

### User Story 2 - PATHの再読み込みに失敗しても既存の動作を壊さない (Priority: P2)

SDD化を実行したユーザーは、環境変数の再読み込み処理自体が何らかの理由（レジストリアクセス不可等）で失敗した場合でも、アプリが異常終了したり、従来から動作していたコマンド検出が壊れたりしないことを期待する。

**Why this priority（この優先度である理由）**: User Story 1の対応はレジストリアクセスという、通常は失敗しないが環境によっては失敗し得る処理を追加する。失敗時の扱いを誤ると、新しい問題（再読み込み失敗によるクラッシュや誤動作）を持ち込みかねないため、堅牢性を独立した観点として明示する。

**Independent Test（独立したテスト方法）**: レジストリからのPATH読み取りが失敗する状況を人為的に再現し、アプリがクラッシュせず、かつプロセス起動時から持っていたPATHでの既存のコマンド検出が引き続き機能することを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） レジストリからのPATH読み取りが失敗する状況、**When**（動作） 手順が実行される、**Then**（結果） アプリは異常終了せず、処理を継続する。
2. **Given**（前提） 上記の失敗が発生した状況、**When**（動作） プロセス起動時のPATHに含まれるコマンド（既存導入済みのツール）を検出する手順が実行される、**Then**（結果） 従来どおり検出に成功する。

---

### Edge Cases（エッジケース）

- ユーザー環境変数PATHとシステム環境変数PATHの両方に同じパスが重複して含まれる場合、結合後のPATH文字列に重複が残ってもよい（Windowsの標準的な環境変数合成でも重複除去は行われないため、既存動作と同じ扱いとする）。
- そもそもレジストリのPATHにも登録されていないコマンド（例: gitが対象PC上のどのPATHにも登録されていない）は、本機能の対象外。この場合は従来どおり「コマンドが見つかりません」という既存の失敗表示になる。
- レジストリの `Path` 値が極端に長い、または不正な形式の場合、読み取りやすい範囲で可能な限り処理し、失敗時はUser Story 2の方針（既存動作を壊さない）に従う。

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-901**: システムは、手順の実行中に新たにインストールされた可能性のある外部コマンドを後続の手順から検出できるようにするため、レジストリに記録されたユーザー環境変数PATHとシステム環境変数PATHを読み直し、現在のプロセスの環境変数PATHへ反映しなければならない。
- **FR-902**: システムはPATHの読み直しにおいて、レジストリ値に含まれる未展開の環境変数参照（`%VAR%`形式）を展開してから反映しなければならない。
- **FR-903**: システムはPATHの読み直しに失敗した場合でも処理を継続しなければならない。失敗時、プロセスが起動時から保持していたPATHはそのまま有効であり、失敗によって既存のコマンド検出動作を壊してはならない。
- **FR-904**: 本修正は、手順自体が外部コマンドを新規にインストールしない場合（対象PC上のいずれのPATHにも登録されていないコマンドを本アプリが導入しない場合）には効果を及ぼさない。既存の「コマンドが見つかりません」というエラー表示・案内文言は変更しない。
- **FR-905**: 本修正はPATH以外の環境変数を変更してはならない。
- **FR-906**: 本修正は既存の5手順（uv導入・specify CLI導入・VS Code拡張導入・Spec Kit足場配置・Git初期化）の実行順序・依存関係・べき等性を変更してはならない。

### Key Entities（主要エンティティ） *(データが関わる機能の場合に記載)*

N/A（本機能はプロセスの環境変数という実行時状態の扱いに関する修正であり、新たな永続データエンティティを導入しない）

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-901**: uvが未導入の環境で「生成」を実行し手順1でuvが新規インストールされたとき、100%のケースで続く手順2が「uvが見つかりません」という誤った失敗にならない。
- **SC-902**: specify CLIが未導入の環境で手順2にてspecify CLIが新規インストールされたとき、100%のケースで続く手順4が「specifyが見つかりません」という誤った失敗にならない。
- **SC-903**: 全ツールが導入済みの環境では、修正前と同じ結果表示・所要時間で成功する（回帰がない）。
- **SC-904**: PATH再読み込みが失敗する状況を人為的に再現しても、アプリが異常終了せず、既存のコマンド検出が引き続き機能する。

## Assumptions（前提事項）

- レジストリの読み取り先は `HKEY_CURRENT_USER\Environment` の `Path` と `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` の `Path` の2箇所とする（Windowsが環境変数PATHを構成する標準的な2箇所）。
- 結合順序はWindowsの既定の合成順（システムPATHが先、ユーザーPATHが後）に倣う。
- 重複除去は行わない（Edge Cases参照）。
- PATHの再読み込みをどの手順の前に行うか（毎回か、インストールが発生した直後のみか等）は `/speckit-plan` で決定する技術判断であり、本specはその選定を指定しない。最も単純な既定は「各手順の実行前に毎回行う」であり、これを妥当なデフォルトとする。
- ビルド構成は Debug で良い（008に引き続きユーザー指示を踏襲）。
