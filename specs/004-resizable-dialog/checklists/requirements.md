## Notes

- 全16項目が合格。`/speckit-clarify` または `/speckit-plan` に進める状態。
- **要求の解釈を確定させた経緯**: ユーザーの当初の説明では「右に引っ張ったときに2つ目のエリアが連動して移動」とあり、添付画像の2つ目の赤枠は画面**下側**の領域だった。方向と対象が食い違うため確認したところ、「1つめが右に引っ張ったとき、2つめが下に引っ張ったとき。どちらも縮めたときは反対の動作」との回答を得た。これにより横方向・縦方向の双方と、拡大・縮小の双方が対象であることが確定した。`[NEEDS CLARIFICATION]` は立てず、確認で解決している。
- **拡大だけでなく縮小も明記した理由**: FR-301 に「拡大時と縮小時の双方で追従する」と書いた。追従処理は拡大方向だけをテストしていると、縮小時に幅や高さが負の値になって表示が破綻する不具合を見落としやすい。ユーザーが「縮めたときは反対の動作」と明示したことも踏まえ、要件として固定した。
- **最小サイズを User Story 2 として独立させた理由**: 追従処理を入れると縮小時に破綻しうるため、下限の制限は追従とセットで必要になる。ただし追従（US1）だけでも価値は成立するので P2 とした。制限が無いとボタンが押せなくなりアプリを終了するしかなくなるため、安全弁として扱っている。
- **動的テストの比重が大きい**: 本フィーチャーは画面の見た目と操作感が成果物であり、その大部分はウィンドウを実際にドラッグしないと確認できない。静的テストで確認できるのは実装の構造に限られる。この非対称は spec のテスト方針に明記した。
- **ST-303（追従方針の網羅検査）を設けた理由**: コントロールごとに追従方針を定めるため、どれか1つを定義し忘れると、そのコントロールだけ取り残されて重なりやはみ出しの原因になる。実装漏れを機械的に検出できるようにした。
- **003 の完了を前提としている**: 対象コントロールは 003 で診断ボタンが廃止された後の構成である。003 より先に本フィーチャーを実装していたら、消えるボタンの追従方針を書くことになっていた。Assumptions に記載済み。
