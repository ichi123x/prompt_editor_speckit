# Feature Specification: 外部コマンドの無応答ハング修正

**Feature Branch**: `008-fix-external-command-hang`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "uvの導入手順(winget install)が対話プロンプト(msstoreソースの利用規約同意)で無期限にハングする不具合を修正する。あわせて、ProcessRunnerの子プロセス監視がReadFileのブロッキングにより実質的にタイムアウトを守れない問題も修正し、外部コマンドが応答を止めた場合に確実にタイムアウトで打ち切れるようにする。"

## User Scenarios & Testing（ユーザーシナリオとテスト） *(必須)*

### User Story 1 - uv導入が対話プロンプトで止まらない (Priority: P1)

uvが未導入の環境で「生成」を実行したユーザーは、winget が初回に表示する msstore ソースの利用規約同意プロンプトによって処理が無期限に停止することなく、成功または失敗のいずれかの結果を受け取れる。

**Why this priority（この優先度である理由）**: 実際の利用時に発生が確認された不具合であり、発生するとアプリを強制終了するしかなくなる。SDD化の入口（手順1）で止まるため、後続の全手順が実行されない致命的な問題。

**Independent Test（独立したテスト方法）**: uvが未導入の環境（または `PATH` からuvを一時的に外した環境）で対象フォルダを選択し「生成」を実行するだけで検証できる。対話待ちのプロセスが残らず、結果一覧の手順1が成功または失敗のいずれかで確定することを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） uvが未導入かつwingetの `msstore` ソース利用規約に未同意の環境、**When**（動作） 「生成」を実行、**Then**（結果） winget install がユーザー入力を待つことなく完了し、結果一覧の手順1に成功または失敗が表示される。
2. **Given**（前提） 手順1の実行後、**When**（動作） タスクマネージャー相当でプロセス一覧を確認する、**Then**（結果） winget および関連する子プロセスが残存していない。

---

### User Story 2 - 外部コマンドが無応答でも確実にタイムアウトする (Priority: P2)

SDD化を実行したユーザーは、手順内で呼び出すどの外部コマンド（uv, specify, code, git 等）が出力を止めて無応答になった場合でも、指定されたタイムアウト時間の経過後に処理が確実に打ち切られ、アプリが無期限に固まらないことを期待する。

**Why this priority（この優先度である理由）**: User Story 1 は既知の1事例だが、根本原因（`ReadFile` のブロッキングによりタイムアウト判定自体が実行されない）は `ProcessRunner` を経由する全ての外部コマンド呼び出しに共通する。P1 の対症療法だけでは類似の未知のハングを防げない。

**Independent Test（独立したテスト方法）**: 出力を止めたまま終了しないダミープロセス（またはそれに相当する無応答コマンド）を短いタイムアウト値で `ProcessRunner` 経由で実行し、指定時間の経過後に処理が戻ってくることを確認する。

**Acceptance Scenarios（受け入れシナリオ）**:

1. **Given**（前提） 起動後に何も出力せず終了もしない外部コマンド、**When**（動作） タイムアウト付きで実行する、**Then**（結果） タイムアウト時間経過後、実際の経過時間としてタイムアウト値に近い時間（同オーダー、無期限ではない）で処理が打ち切られ結果が返る。
2. **Given**（前提） タイムアウトで打ち切られたコマンド、**When**（動作） 処理が戻った直後、**Then**（結果） そのコマンドのプロセス（および必要な子プロセス）が終了しており、システムに残存しない。

---

### Edge Cases（エッジケース）

- winget自体が対象PCに存在しない場合、既存どおり「winget が見つかりません」という失敗として扱われるか?
- msstoreソースの利用規約に既に同意済みの環境で実行した場合、動作に変化がない（従来どおり成功）ことを確認する。
- ネットワーク遮断によりwingetのダウンロードが極端に遅い場合、それは無応答ハングではなく低速な進行であり、既存のタイムアウト（10分）でこれまでどおり打ち切られる。
- タイムアウトで `TerminateProcess` した対象が、さらに子プロセス（例: winget が起動した msstore 関連プロセス）を持つ場合、それらも残存しないこと。

## Requirements（要件） *(必須)*

### Functional Requirements（機能要件）

- **FR-801**: システムは uv 導入手順（`winget install`）の実行時、ソースおよびパッケージの利用規約確認プロンプトに対しユーザー入力を要求せず、自動的に処理を進めなければならない。
- **FR-802**: システムは外部コマンドを実行する際、そのコマンドが出力を停止し無応答になった場合でも、指定したタイムアウト時間の経過後に確実に処理を打ち切らなければならない（出力の有無にかかわらずタイムアウトを判定できること）。
- **FR-803**: タイムアウトにより打ち切られた手順は、他の失敗ケースと同様に結果一覧へ「失敗」として理由付きで表示されなければならない。
- **FR-804**: タイムアウトにより打ち切られた外部コマンドのプロセスは、処理が戻った時点で終了していなければならず、残存プロセスを残してはならない。
- **FR-805**: 本修正は既存の5手順（uv導入・specify CLI導入・VS Code拡張導入・Spec Kit足場配置・Git初期化）の実行順序・依存関係・べき等性を変更してはならない。
- **FR-806**: 本修正は `ProcessRunner` を利用する既存の全呼び出し（uv, specify, code, git）に等しく適用され、特定コマンドだけの特別扱いをしてはならない（原則III YAGNI、単一の仕組みで解決する）。

## Success Criteria（成功基準） *(必須)*

### Measurable Outcomes（測定可能な成果）

- **SC-801**: uv未導入かつwinget利用規約未同意の環境で「生成」を実行したとき、100%のケースでユーザー入力なしに手順1の結果（成功または失敗）が確定する。
- **SC-802**: 外部コマンドが応答を止める状況を人為的に再現した場合、設定されたタイムアウト時間から大きく超過することなく（同オーダーの時間内に）処理が打ち切られ、結果欄に反映される。
- **SC-803**: 修正後も、正常に完了する既存の5手順のシナリオでは、これまでと同じ結果表示・所要時間で成功する（回帰がない）。
- **SC-804**: 本不具合に起因するアプリの強制終了（タスクマネージャー等での手動終了）が不要になる。

## Assumptions（前提事項）

- 対象環境には winget（Windows 11既定のApp Installer）が導入済みであるという既存の前提を継続する。winget自体が存在しない場合の扱い（`CommandNotFoundReason`）は変更しない。
- msstore ソースの利用規約への同意可否をアプリが自動で肯定することは許容される（uv自体は winget公式ソースの `astral-sh.uv` パッケージとしてのみ導入され、msstoreストア版が別途導入されるわけではない）。
- 「確実にタイムアウトで打ち切る」ための実装手段（監視スレッド、オーバーラップI/O等）は `/speckit-plan` で決定する技術判断であり、本specはその選定を指定しない。
- ビルド構成は Debug で良い（ユーザー指示）。Release相当の追加検証は本機能の範囲外とする。
- 既存のタイムアウト値（uv導入: 10分、他手順: 各手順ごとの既定値）は変更しない。タイムアウトが「効くようになる」ことが本修正の目的であり、値自体の見直しはスコープ外。
